# Internal Runtime DOX

## Purpose

- Own the provider-neutral runtime, channel adapters, harnesses, durable state, extension hooks, and workspace initialization.

## Package Ownership

- `app` composes screens, live settings, channel and harness supervisors, histories, commands, hooks, captured runtime logs, startup registration, conversation branching, the active agent-job registry, private workspace-local bounded job archives with durable wrapping numeric references, and the Pi session-control command surface with automatic first-session naming, conversation-label routing, and its downstream new-session disclosure. Archived event text is redacted inspection data only; live execution state and evidence-based health remain distinct.
- `agentdocs` owns curated offline behavior topics, stable references, deterministic bounded pagination/search, versioned structured output, and concise `/help` topic metadata. It never reads workspace or runtime state.
- `channel` owns the common transport contract, hot-reload lifecycle supervision, the optional best-effort conversation-label capability, and TUI, Telegram, and WhatsApp adapters. The TUI owns a narrowly scoped MIT-licensed Bubbles v0.21 textarea derivative because the upstream private wrapper splits fitting extended graphemes; keep its editor behavior aligned with that dependency while preserving grapheme-atomic wrapping, navigation, deletion, and character transposition.
- `cli` owns public command parsing and process lifecycle.
- `config` owns canonical `.spynel/config.yaml` defaults, workspace-root-relative path resolution, validation of current settings with unused input keys ignored, and the fixed `.spynel` state root.
- `core` owns messages, responses, stable cross-package value types, and the shared compact count formatter used by constrained status indicators.
- `extensions` owns executable hook discovery and Git installation.
- `fsx` owns cross-platform atomic file replacement and no-clobber publication of complete new files.
- `history` owns independent append-oriented channel history, explicit per-conversation clearing, bounded prompt-context rendering that always carries the current user entry, disk-backed discovery and latest-conversation selection, and point-in-time branching into a requested target channel.
- `instance` owns cross-platform workspace-server election, the stable private-token-derived loopback-environment identity, lock-free discovery of atomically published authenticated rendezvous records, five-second renewal, 30-second stale detection, fenced stale takeover, and expiring target-specific handoff.
- `localapi` owns versioned committed conversation subscriptions/snapshots, optional private Unix socket access, and the private authenticated loopback contract through which every TUI and plain CLI client identifies its caller instance, rejects known-foreign loopback owners before dialing, uses bounded sanitized startup readiness, reaches the elected application service, streams messages, obtains typed status, and observes bounded shared state.
- `markdown` owns GitHub-flavored Markdown rendering for ANSI terminals, including standard OSC 8 hyperlinks for explicit absolute-file and URI links, conversion to Telegram HTML or WhatsApp-native formatting, deterministic Telegram HTML chunking within parsed-visible limits with balanced formatting, grapheme-aware boundaries, and bounded truncation, and HTML-escaped literal plain-text chunking that renders user-supplied transcript echoes without interpreting them as Markdown.
- `media` owns bounded streamed attachment storage, validated outbound file directives, the provider-neutral transcription contract with its shared marker strings, serialized local Parakeet transcription through miniaudio/Ogg-Opus/sherpa-onnx, the ElevenLabs Speech-to-Text client, the sentinel-only missing-key fallback wrapper that selects between them, and the coordinated versioned per-user cache for automatically managed speech models.
- `harness` owns the harness interface and follow-up capabilities, centralized catalog/factories, transactional runtime supervisor, Codex app-server, Claude Code print mode, Agent Zero CLI and other fixed ACP aliases, Pi JSONL RPC, the shared stable-v1 ACP stdio implementation, and the optional provider-neutral session inspection, naming, compaction, and import capabilities, plus startup/earliest-negotiation diagnostics and portable test-binary provider fixtures. Queue-mode chat bursts are batched without merging job-control boundaries.
- `shortid` owns compact eight-alphanumeric-character rendering of opaque IDs for human-facing output; full identifiers remain authoritative internally.
- `startup` owns reversible, workspace-specific systemd, launchd, and Windows Task Scheduler registration.
- `theme` owns validated, file-backed semantic color palettes, embedded YAML assets, and no-clobber installation of editable workspace copies.
- `updater` owns per-installation npm/GitHub detection, launcher startup snapshots, bounded source checks, complete validated native bundle installation, and stable standalone restart paths.
- `workspace` owns initialized filesystem structure and embedded, user-overridable workspace assets; it delegates built-in palettes to `theme`.

## Local Contracts

- Avoid package cycles by keeping cross-boundary values in `core` and interfaces beside their consumers.
- Configuration changes from forms and commands share the typed `config.Setting` catalog, are validated as a complete transaction, persist through an atomic `0600` replacement, and publish only the newest snapshot. Never place secret setting values in status output, framework replies, or durable conversation history. Telegram and WhatsApp fail closed: neither can be enabled without a valid canonical sender whitelist, neither can replace that whitelist with missing, malformed, punctuation-only, or normalization-empty values while enabled, and each adapter resolves the current live list at supervisor preflight, startup, every inbound event/queued message, and every pairing, provider, or proactive-delivery boundary. Invalid authorization reports and retains a connection error before downstream history, media, activity, commands, agent dispatch, replies, attachments, or hooks; it wakes the active adapter loop so Telegram closes polling/webhook service and WhatsApp disconnects, while the supervisor does not retry the unchanged invalid fingerprint or live authorization loss. The supervisor revokes stale instances before cancellation; Telegram's sole post-revocation provider exception is teardown-only `deleteWebhook`, which prevents a stopped local listener from remaining registered. Enabled Telegram webhook mode additionally requires header-secret verification, and connection status must never expose its public URL or per-token path. Normalize WhatsApp allow-list comparisons to canonical international digits so `+`, `00`, spaces, and punctuation are equivalent while letters and values beyond 15 digits are invalid; in self-chat mode resolve an incoming LID to the paired phone-number identity before authorization and conversation keying. Telegram accepts positive IDs or ASCII letter/digit/underscore usernames and links the whitelist description and wizard to the third-party `@userinfobot` helper for discovering numeric user IDs.
- WhatsApp socket reachability before device linking is pairing readiness, not a connected channel. Report `connecting` with pairing detail until the credential store has an authenticated device ID; only a paired connection may report `connected`. A connected status may expose the validated phone-number JID as `+<number>` with its official `https://wa.me/<number>` link in the TUI WhatsApp status section; never expose opaque LIDs or non-phone JIDs as account identities. Never expose QR render data on the general WhatsApp settings screen: retain it only for the pairing wizard's dedicated fullscreen QR action.
- Identify new WhatsApp QR-linked devices as `Spynel` with desktop companion metadata and an Electron QR client type instead of whatsmeow's generic unknown-device defaults. Keep phone-number code pairing on a server-accepted browser/OS display name because WhatsApp rejects arbitrary values there. Initialization probes non-custom profiles in catalog order from `PATH` and conventional per-user locations, and Agent Zero is available only when bounded `a0 acp --check` capability discovery succeeds. Default `harness.sandbox` to `danger-full-access`, expose the validated `danger-full-access`, `workspace-write`, and `read-only` choices. Commit model selection under the harness-dispatch admission fence so active work retains its captured model and the next provider dispatch, including a queued continuation, uses the newest committed model. Apply harness implementation, command, argument, and sandbox changes transactionally only while idle. Derive built-in executables, every working directory, approval policy, and network flag internally; preserve the historical `medium` effort when a legacy configuration omits the new key, while explicit inherit uses provider defaults.
- Optional provider-neutral session inspector, namer, compactor, importer, and conversation-context capabilities keep application code harness-neutral; only the Pi adapter implements them, the supervisor forwards them, and unsupported session controls return an explicit error while conversation-context queries report false so callers fall back to the safely bounded seed. Session naming is metadata-only and best-effort: after a successful non-steered dispatch that creates a conversation's first session, the application derives a bounded label from the accepted user content, names the session with an existing-name-preserving request, and routes the effective provider name to the optional conversation-label capability as a non-forced automatic request that the transport applies at most once per conversation and process, while `/pi name <name>` explicitly names an existing session and force-renames a private Telegram topic. Naming failures never affect the turn or reply and are not retried, and the application inspects the pre-dispatch session identity on every surface while disclosing it only through the allowed-surface notice. Pi session controls are exposed only through `/pi` in the local TUI and canonical private Telegram conversations; the plain CLI, WhatsApp, groups, forum topics, malformed routes, and other channels refuse before the capability boundary. The first successful non-continuing final after an ordinary allowed-surface prompt that creates or rotates a session receives a prepended full-ID notice that is added downstream of hooks, media, history, and job archival.

Model and supported-harness effort lists end with Custom text entry even when discovery fails. Explicit model/effort identifiers pass through without catalog membership checks; the provider validates support. Validate service modes against metadata and resolve invalidated stored properties to inherit unless the transaction explicitly supplies an effort. Retain ACP's unsupported effort boundary.
