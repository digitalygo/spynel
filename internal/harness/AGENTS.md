# Harness Adapter DOX

## Purpose

- Own the provider-neutral harness interface, catalog/factories, transactional supervisor, and Codex, Claude Code, Agent Zero CLI, Pi, and ACP process adapters.

## Local Contracts

- Keep application code harness-neutral; adapters map native events into the common response and follow-up contract.
- Codex maps strictly boolean `error.willRetry: true` to nonterminal `reconnecting` status, retaining diagnostics in captured events. Only nonempty agent-message, reasoning, or plan deltas for the exact active turn restore `running`; tool output and generic activity do not establish upstream recovery. Missing/false/malformed retry flags remain errors. Serialize admission, deferred replay, live notifications, and transport failure through callback publication; publish admission first and reject another turn's late events. Transport failure also fences pending admission so a successful RPC reply cannot resurrect an exited provider.
- Resume Codex threads with `excludeTurns: true`: Codex retains its conversation context, while Spynel consumes only thread identity and its own bounded history. Any resume failure preserves the saved session and rejects dispatch instead of silently creating a replacement conversation. Keep the shared 16 MiB message bound; overflow and EOF close provider stdin as well as cancelling the subprocess so npm-launched native children receive EOF, fail pending/active work, and remain visibly unavailable through the supervisor until explicit restart or successful reconfiguration. Overflow diagnostics inspect only a bounded envelope prefix to identify a known notification or the correlated pending RPC, report unavailable metadata explicitly, and name the message-size limit and reconnect action without exposing payloads, provider IDs, arbitrary method strings, or replaying interrupted requests.
- Declare native-steer versus queued follow-up behavior explicitly, fence active executions, and invoke durable iteration reservation exactly once immediately before accepted provider delivery.
- Expose the provider-neutral new/steered/queued conversation admission classification at the same session fence so application correlation can cover consolidated terminal responses exactly.
- When an ordinary queued follow-up replaces an emitter, deliver its predecessor's continuing result followed by an explicit done-status release. This closes every request and balances application/channel activity without claiming logical completion. Control deliveries that preserve their emitter do not release it.
- An interruption attempt cancels not-yet-dispatched ordinary follow-ups with a terminal error per request, including every emitter in a dequeued batch. Capture the cancellation generation when removing queued work, preserve it through batching, and reject stale dispatch even if a successor turn is active. Queued controls retain their shared emitter; only the provider owns that execution's terminal event. Failure to interrupt the active provider does not restore already-cancelled queued requests.
- Order forward-looking model commits and dispatch snapshots under one supervisor fence. Never mutate an already-admitted provider turn; native steering remains part of that turn, while queued continuations and later top-level turns snapshot the newest model at their own provider-dispatch admission.
- Extend that fence to reasoning effort and service mode. Catalog metadata declares effort support for Codex, Claude, and Pi. Their model and effort values pass through to the provider without requiring discovery or catalog membership; validate bounded effort syntax at the shared boundary and let provider errors report unsupported manual choices. Codex reads per-model effort/service tiers for detected choices and passes `effort`/`serviceTier`; service selections still require verified capabilities. Claude passes `--effort`. Pi identifies its current/default model and current thinking level from `get_state`, queries each catalog model's exact RPC thinking levels in a separate no-session process selected by the non-persistent `--model` runtime override, labels a default effort only for the authoritative current model, and passes `--thinking`; never use Pi's persistent `set_model` RPC for capability inspection. Both legacy omitted and explicit Pi efforts reach the provider for validation/clamping. ACP model selection remains supported, but reasoning and speed are unsupported because ACP advertises optional thought choices only after session creation and defines no standard speed category.
- Build commands without shell interpolation, bound scanner/event payloads, surface startup and negotiation diagnostics, and keep portable fixture providers synthetic.
- Launch Pi RPC with `--mode rpc` plus only Spynel's own session, model, thinking, and sandbox arguments so the user's ordinary global extensions, skills, prompt templates, themes, context files, and model/provider settings load; never pass resource-suppression flags or an approval override, and leave project-local resource loading to Pi's own non-interactive trust decision. The one additive Spynel resource is the Telegram final-replies note extension: every process launch for a `chat:telegram:` conversation key, whether fresh, resumed, forked, or restarted, materializes the dependency-free embedded extension as the private `0600` current-user-owned regular file `.spynel/runtime/spynel-telegram-note.js` (never a symlink or another non-regular entry) and passes exactly one `--extension <path>` argument, replacing drifted content, permissions, or ownership atomically through a temporary file and one rename that never follows the target, with the published file revalidated afterwards. Before materialization, the `.spynel` state root and the runtime directory beneath it are validated by Lstat as real, current-user-owned directories with no group or other permission bits: missing ones are created `0700`, and a pre-existing directory that violates that private trust contract fails the launch closed instead of being chmodded or replaced, so a symlinked, shared, or foreign-owned runtime can never redirect or rewrite the executable extension; a directory occupying the target path fails the launch instead of being deleted. Loading is additive, so Pi keeps discovering global and trusted-project `SYSTEM.md` and `APPEND_SYSTEM.md` files and loads ordinary global extensions, skills, prompt templates, themes, and context files unchanged. On `before_agent_start` the extension assigns exactly one namespaced `spynel_telegram` system-prompt section, wrapped by Pi as `<spynel_telegram>`, that describes final-replies-only turn behavior; it never returns a system prompt, forces a prompt, prepends user messages, registers commands or tools, or touches project trust or resources. Ephemeral discovery processes and every other channel never load it, and the note is never a message prefix or extra provider turn. The note is guidance, not enforcement: a user extension that returns a forced prompt can override it, and extension-triggered model runs may bypass `before_agent_start`, so no model-compliance guarantee is claimed. Pi user/global resources belong to the user's Pi installation and remain separate from Spynel's explicitly installed executable hooks. Because a trusted extension set can request interactive UI, answer blocking `extension_ui_request` dialogs (`confirm`, `select`, `input`, `editor`) with an immediate explicit cancellation and one provider-neutral status event, never respond to fire-and-forget methods, and keep the response write under the existing stdin mutex so no dialog can stall a headless turn.
- Pi is the only adapter implementing the optional provider-neutral `SessionInspector`, `SessionNamer`, `SessionCompactor`, and `SessionImporter` capabilities; `Supervisor` forwards them and returns `ErrSessionControlsUnsupported` for every other harness. Inspection reports the durable session ID, path, and configured command without starting a provider. Naming is metadata-only and never creates or rotates a session: `SetSessionName` requires the stored session identity to match `expectedSessionID`, reuses a matching live non-closed process even during an active turn, and otherwise requires the stored session file to be a readable regular file before resuming exactly that session. The live path intentionally accepts a pre-flush session: Pi reports the assigned session file path during `get_state` negotiation but defers creating the JSONL file until the first assistant message persists, so naming the matching live process works before that file exists while a persisted resume still fails closed on a missing or non-regular file, and a live RPC failure never falls back to a resume. The adapter optionally preserves and returns an existing provider name when `onlyIfEmpty` is set, sends RPC `set_session_name`, and reports the normalized name plus changed state read back from `get_state`. Manual compaction resumes an existing persisted, policy-matching, idle session, sends Pi RPC `compact` with at most 4096 Unicode-code-point custom instructions, and maps bounded `tokensBefore`/`estimatedTokensAfter` counts without creating or replacing a session. Import accepts only a full canonical lowercase UUID, performs bounded symlink-free read-only discovery over the effective Pi session roots (`PI_CODING_AGENT_SESSION_DIR`, project or global `settings.json` `sessionDir`, then the agent sessions directory), requires a supported regular JSONL header with the exact ID and matching harness cwd, forks with `--fork <validated-source>` into the workspace-local `pi-sessions` directory, verifies a distinct in-directory fork before persisting, fails closed when the source changes during the fork, and removes only a reported fork file that a pre-operation directory snapshot proves was absent. A fork file created before `get_state` reports its path stays an inert unreferenced orphan because guessing a path could delete another conversation's session. Control errors stay bounded and redact session and workspace paths.
- `ConversationContextProvider` is an optional provider-neutral capability that answers whether an ordinary send for a key would reuse a provider session that already retains the conversation. Implementations never return an error and report false on absence, uncertainty, I/O failure, stale policy, unsupported, or unavailable provider state, because false always safely selects the bounded-history seed. Only Pi implements it today: a live active turn, a live idle process with matching policy, or a persisted policy-matching session whose regular file exists reports true, while a fresh session, policy mismatch, missing or non-regular session file, closed or not-started harness, and every uncertainty report false. `ThreadID` and `SessionInspector` are not substitutes because neither proves the provider can reuse the retained conversation. The supervisor forwards the capability and reports false for a closed or unavailable target and for a harness without it.
- `NativeConversationInputProvider` is an optional provider-neutral capability that answers whether an ordinary send for a key delivers the raw accepted conversation text that the harness expands with its own native skills, prompt templates, and extension commands. The supervisor forwards it and reports false for a closed or unavailable target and for a harness without it. Only Pi implements it today: ordinary `chat:<channel>:<conversation>` keys report true, while control and unknown keys report false so callers keep the provider-neutral bounded-context prompt.
- Raw accepted conversation text keeps Pi's own slash semantics. Ordinary chat dispatch during an active turn delivers slash-shaped input with RPC `prompt` and `streamingBehavior:"steer"` because Pi rejects extension commands on `steer`; through that form Pi executes recognized extension commands immediately, expands skills and prompt templates, and queues unknown slash names, with the same delivery order, durable iteration reservation, and emitter transfer as ordinary steering. Control-plane `Steer` deliveries keep the strict `steer` command so delimited coordination text is never interpreted as a command. An idle dispatch whose slash name `get_commands` reports as a registered extension command settles through post-response `get_state` idle confirmation: Pi awaits the command handler before emitting the prompt response and an accepted ordinary prompt is already streaming when the client sees that response, so an idle `get_state` is positive evidence the command was handled without a model run and no `agent_settled` will arrive. That settlement emits one plain status plus the ordinary empty final and never fabricates a model answer from the RPC acknowledgment; any handler-started run, including one that already settled the turn before the response, keeps ordinary `agent_settled` settlement authoritative, and a failed recognition query keeps the ordinary event-driven lifecycle.
- Keep Pi turn settlement success-first. A settled run with at least one successful assistant message always emits one final terminal: `Event.Text` joins only the successful assistant messages with newlines, and `Event.FinalText` is the last successful message. A failed assistant message and its streamed text stay live-visible but contribute nothing to the settled result, because Pi drops each errored message from agent state and retries it inside the same still-unsettled run (`auto_retry_start`, exponential backoff, attempt count from the user's own Pi `retry` settings, which Spynel never overrides). A later success clears the pending error, a later failure after a success never suppresses the answer, and `EventError` is emitted only when the run settles with no successful assistant message. `auto_retry_start` and `summarization_retry_scheduled` remain nonterminal status, process-failure behavior is unchanged, and remote transports still receive only the last non-continuing final or terminal error.
- Keep Agent Zero CLI as the fixed `agent-zero` profile backed by the shared ACP adapter, launch `a0 acp`, and require a bounded successful `a0 acp --check` before reporting it available.
