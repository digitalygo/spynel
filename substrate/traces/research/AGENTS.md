# Research trace DOX

## Purpose

- Own dated research records that capture codebase findings and analysis before implementation planning or remediation.

## Local Contracts

- Name research files `YYYY-MM-DD-description.md`.
- State scope, exclusions, revision context, findings, evidence, limitations, and ordered recommendations when applicable.
- Cite exact repository paths and line numbers for consequential code claims.
- Distinguish source-verified behavior from inference, threat-model-dependent findings, and candidates that still require reproduction.
- Never claim a vulnerability, test result, deployment, or external state was verified when the recorded method did not verify it.
- Keep research read-only in intent. Implementation steps belong in plans, operations, or tasks rather than being recorded as completed work here.
